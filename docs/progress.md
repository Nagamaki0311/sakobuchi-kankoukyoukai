## 2026-09-02 T-003: kiroku.htmlの恐怖演出強化

### 実施内容
- ユーザーから「kiroku.html（隠しページ）の恐怖演出をリアリティラインを壊さないレベルで強化したい」という依頼を受け、既存の演出（文字コード変換エラーを装った文字化け、本文全体を1文字ずつ揺らすCSS、候文調の由来記）を踏まえた案を複数提示した。静的な案（揺らぎのメリハリ／侵食の段階化／サイドバーのエラー情報追加／結びの改ざん演出／ソースコード内コメント）とアニメーション案（一部の文字の常時微振動／読み込み時の一度きりの明滅／背景ノイズのオーバーレイ／間欠的な一瞬の乱れ）をそれぞれ表で整理し、常時動き続ける演出（背景ノイズ）は「静止した記録を偶然開いてしまった」という既存の空気と相性が悪いとして非推奨とした。
- ユーザーが「静的案のA（メリハリ）・C（エラー情報追加）・D（結びの改ざん）」と「アニメーション案のB（読み込み時明滅）・D（間欠的な乱れ）」の組み合わせを選択したため、以下を実装した。
  - **メリハリ化**: 本文の揺らぎ文字（1文字ずつ`<span>`でtransform/color/opacityをランダム化している箇所、計710文字）のうち、通常の文字は揺れ幅（translate/rotate）を約45%に減衰し不透明度の下限を0.85へ引き上げて静める一方、由来記の核心語（天女・磔・儀・祟り・供え・凶事・縛る、計24文字）だけ色を`#8a0000`に統一し不透明度1・太字・揺れをやや強調して、既存の「均一に揺れて何が異常か埋没する」状態から強弱のあるコントラストへ変更した。文字自体（テキスト内容）は一切変更していない。
  - **サイドバーのエラー情報追加**: 既存の`Fatal error`ボックスに「最終更新: 1978-00-00 00:00」（存在しない日付）「上書き試行: 3回（失敗）」の2行を追加した。
  - **結びの改ざん演出**: 最後の一文「以上、聞き伝えのままここに記す。」の後に、同じ書き出しを繰り返した上で「以上、聞き伝えの……」と尻切れにする文を追加し、末尾に向けて不透明度を下げるフェードアウトを付けた。
  - **アニメーション**: `@keyframes kiroku-flicker-in`（読み込み時に不透明度が数回明滅した後1で静止する、`animation-iteration-count:1`相当のsteps関数）をサイトタイトル・お知らせ見出し・エラー情報見出しに適用した。`@keyframes kiroku-glitch-pulse`（9秒周期のうち終盤の数%だけ不透明度とtext-shadowが一瞬乱れる）を上記24文字の核心語spanに適用し、文字ごとに`animation-delay`をずらして同期しないようにした。いずれも各spanの`transform`（文字ごとに固有のtranslate/rotate値）には触れず、opacity/text-shadowのみをアニメーションさせることで、既存の「揺らぎ文字」の見た目を壊さないようにした。
- 実装はPythonスクリプトでHTMLをパースし、正規表現でspanのstyle属性を解析・再生成する形で行った（710文字の手作業編集は非現実的なため）。

## 2026-09-02 T-006: GitHub Pages公開確認とkiroku.htmlのグリッチ演出の置き換え

### 実施内容
- ユーザーからGitHub Pagesを有効化した旨の連絡を受け、公開URL（`https://nagamaki0311.github.io/sakobuchi-kankoukyoukai/`）のindex.htmlとkiroku.htmlをWebFetchで確認した。index.htmlは正常に表示され、フェイクリンクが404.htmlへ遷移するのも設計通りだった。kiroku.htmlはWebFetchのAI要約が「致命的なエンコードエラーが発生しているページ」と誤認するほど、文字化け演出が意図通り機能していることを確認した。
- ユーザーから、T-004で対応した後もなお核心語の色・text-shadow明滅演出（`kiroku-glitch-pulse`）がチープに見え恐怖効果を薄めているという指摘を受けた。ユーザーは「削除もしくは完全に別のアニメーション演出（42秒おきに画面全体に影響・ゆがむグリッチ）にしてみるなど」と提案した。
- 文字単位の演出を撤去し、42秒周期のうち約0.5秒（97%〜98.2%の区間）だけ`#page-wrap`全体にtranslate・skewX・filter（invert/contrast/saturate/hue-rotate）を`steps(1,end)`で断続的に適用する`kiroku-screen-glitch`アニメーションへ置き換えた。核心語24文字spanに付与していた`animation:kiroku-glitch-pulse ...;`のインラインプロパティも正規表現で一括除去し、`@keyframes kiroku-glitch-pulse`定義自体も削除した。読み込み時の一度きりの明滅（`kiroku-flicker-in`）は指摘対象外のためそのまま維持した。

### 結果
- `<span>`・`<p>`・`<div>`のタグ開閉数が編集前後で一致することを確認した。
- 42sという周期はPlaywrightでの目視確認に不向きなため、`kiroku-screen-glitch`のduration値のみを2sに置き換えた一時ファイルを別途作成し、`getComputedStyle`を5ms間隔でポーリングして`transform`・`filter`の値を監視した。約2.34秒地点で`matrix(1, 0, 0.0349208, 1, 8, -6)`・`filter:invert(1)`（97.4%キーフレームに相当する値）が実際に適用されることを確認し、一時ファイルは削除した。本番の`kiroku.html`（42s版）はこのロジックをduration以外変更していないため、同じ挙動になる。

### 結果

## 2026-09-02 T-010: ブラウザの強制ダークモード対策（color-scheme宣言の追加）

### 実施内容
- ユーザーから「Xでリンクを開くとサイトの背景が暗いダークモード的な表示になった」という報告を受けた。3ページ（index.html/kiroku.html/404.html）を調査し、いずれも`<meta name="color-scheme">`や`color-scheme` CSSプロパティを宣言していないことを確認した。
- 明示的な配色宣言がないページは、Xのアプリ内ブラウザ（Chromiumベース）やAndroidの一部ブラウザが持つ「強制ダークモード」機能により、システム側がダークモード設定の場合に自動的に色を反転・変色させられることがある。このサイトはCSSで色を直接指定した固定デザイン（kiroku.htmlは意図的な暗い配色を含む）であり、閲覧環境によって自動的に配色が変わることは意図していないため、これが原因と判断した。
- 3ページ全ての`<meta charset="UTF-8">`直後に`<meta name="color-scheme" content="light">`を追加し、ブラウザの自動ダーク化を明示的に無効化した。

### 結果
- 3ページとも`<span>`・`<div>`のタグ開閉数が編集前後で一致することを確認した。

### 次回開始位置
- 特になし。ユーザー側でX等のアプリ内ブラウザから再度リンクを開き、意図通りの配色で表示されるか確認する。

## 2026-09-02 T-012: kiroku.htmlに文字が枠外へ逸脱する演出を追加

### 実施内容
- ユーザーから実機（Firefox、独自ドメイン`sakobuchi.nk-pr.com/kiroku.html`）のスクリーンショットが提示され、「現状何が足りないと思うか」という質問と共に「テキストが既存の枠外へ逸脱するのもありかなと思っている」という提案を受けた。
- スクリーンショットを確認し、文字ごとの揺らぎ（色・回転・サイズ）はあるものの、テーブルの枠・見出しバー・サイドボックスの境界線は一切乱れず整然としたままである点を指摘した。「内容は異常だが、それを収める構造は健全なまま」という状態が、演出を装飾的な範囲に留めている要因と分析し、ユーザー提案の「枠外への逸脱」がこのギャップを埋める効果的な方向性であることを説明した。
- 実装方針として、全文字に適用すると単なるレイアウト崩壊に見えるリスクがあるため、既存の核心語（磔・祟り、間欠的グリッチアニメーションの対象と重複）と結びの改ざん文の3箇所のみに絞ることを提案し、ユーザーの同意を得て実装した。
- 対象spanのtransform値を、通常の揺らぎ（translate: 数px、rotate: -12〜12deg）から大きく逸脱した値（例: 磔は`translate(-6px,120px) rotate(38deg) scale(2.1)`）に置き換え、`position:relative; z-index:5;`を付与した。文字spanの`transform`はドキュメントフローに影響しないため、周囲のテーブル・box構造の寸法は変更せず、視覚的にのみ枠を越えさせている。
  - 「磔」（について section）: 下方向へ大きく逸脱し、次の見出しバー（沿革・歴史）へ突き抜ける
  - 「祟り」の「り」（沿革・歴史 section）: 右下へ千切れるように移動し、本文から浮遊した状態にする
  - 結びの改ざん文の一部「の」（アクセス section末尾）: 大きく下方向へ落ち、footerの外側（濁った湖の背景）まで到達する

### 結果
- `<span>`・`<p>`・`<div>`のタグ開閉数が編集前後で一致することを確認した（span: 720/720、breakoutクラス付与3箇所）。
- Playwrightでレンダリングし、3箇所とも意図通り視覚的に枠を越えて表示されること、周囲のテーブル・見出しバーの寸法・配置自体は崩れていないことを確認した。
- 初回のフルページスクリーンショットで見出しバーの色が一時的に薄く見えたため、待機時間を伸ばして再検証したところ再現せず、`kiroku-flicker-in`アニメーションの撮影タイミングによる一時的な現象であり今回の変更由来ではないと判断した。
