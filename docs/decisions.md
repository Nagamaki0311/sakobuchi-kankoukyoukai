# 設計判断記録 (ADR)

設計判断、採用理由、変更履歴を記録する。新しいエントリは末尾に追加する（古い順）。

## 記録フォーマット

```
## D-XXX: タイトル

- 日付: YYYY-MM-DD
- 状態: 採用 / 却下 / 廃止（廃止の場合は後継のDを記載）

### 背景
- なぜこの判断が必要になったか

### 決定
- 何を決定したか

### 理由
- なぜその選択をしたか（検討した代替案があれば併記）

### 影響
- この決定が及ぼす影響、制約
```

## D-001: kiroku.html（隠しページ）をpublicリポジトリのまま公開する

- 日付: 2026-09-02
- 状態: 採用

### 背景
- `kiroku.html`は、index.htmlの「沿革・歴史」セクションにある「誤り」という一語からのみ遷移できる隠しページで、本作品の核心的なネタバレを含む。引き継ぎ資料（CLAUDE_CODE_HANDOFF.md）は、publicリポジトリのままだと誰でもGitHub上で内容を読め検索エンジンにもインデックスされうるため、隠しページの仕掛けが機能しなくなる可能性があるとして、公開範囲の判断をユーザーに委ねるよう指示していた。
- 本リポジトリ（nagamaki0311/sakobuchi-kankoukyoukai）は、このタスク着手時点で既にpublicとして作成済みだった。

### 決定
- リポジトリの可視性は変更せず、`kiroku.html`を含むサイト一式をpublicのまま追加する。

### 理由
- ユーザーが「公開のまま追加（何もしない）」を明示的に選択した。
- 隠しページとしての仕掛けは、あくまで「index.htmlに明示的なリンクを置かない」という作中演出であり、GitHubリポジトリの可視性とは別の層の問題として運用する。

### 影響
- `kiroku.html`の内容はGitHub上で誰でも閲覧・検索可能な状態になる。作中の「隠しページを発見する」体験は、サイト自体（index.html経由でのみ気づける）で完結させる前提とする。
- robots.txtによる除外やsitemapからの除外は今回実施しない。GitHub Pagesでの公開等、公開範囲に関わる追加判断が必要になった場合は改めてユーザーに確認する。

## D-002: GitHub Pages公開時にrobots.txtでクロールを拒否する

- 日付: 2026-09-02
- 状態: 採用

### 背景
- ユーザーから「サイトのリンクを出せますか」という依頼があったが、この時点ではGitHub Pages等の公開設定を行っておらず、サイトのURLが存在しなかった。
- GitHub Pagesで公開する場合、D-001で保留していた「robots.txtでの除外」（引き継ぎ資料CLAUDE_CODE_HANDOFF.mdが選択肢として挙げていた対応）を実施するかどうかの判断が必要になった。

### 決定
- GitHub Pagesで公開する。あわせてリポジトリ直下に`robots.txt`（`Disallow: /`）を追加し、検索エンジンによるクロールを拒否する。

### 理由
- ユーザーが「robots.txtで除外しつつ公開」を明示的に選択した。
- D-001でリポジトリ自体はpublicのまま維持する判断をしているため、robots.txtによる対応はGitHubリポジトリ上での閲覧可能性には影響せず、検索エンジンのインデックス化のみを防ぐ効果に限定される（URLを直接知っていればアクセス可能な状態は変わらない）。

### 影響
- `kiroku.html`を含むサイト全体が検索エンジンにインデックスされにくくなるが、URLを知っていれば誰でも閲覧できる状態は変わらない。
- GitHub Pagesの有効化自体（リポジトリ設定のSettings > Pages）は、この環境で利用可能なツール（GitHub MCP Server、`gh` CLI）から操作できないため、ユーザー自身の手動操作が必要となる。

## D-003: kiroku.htmlの恐怖演出強化を、既存の演出技法の再配分とアニメーションの一部追加で行う

- 日付: 2026-09-02
- 状態: 採用

### 背景
- ユーザーから「kiroku.htmlの恐怖演出をリアリティラインを壊さないレベルで強化したい」という依頼があった。既存の演出は、文字コード変換エラーを装った文字化け（ヘッダー・ナビ・パンくず）と、本文の由来記全体を1文字ずつ`<span>`でランダムに揺らすCSSの2本柱で構成されていた。
- 本文全体が均一に揺れているため、由来記の中でも特に恐怖の核心となる語（磔・儀・祟り等）が周囲の文字と同じ強度で埋没しており、強弱のコントラストが効いていなかった。
- CSS3の`@keyframes`アニメーションは2000年代初頭の技術水準とは厳密には矛盾するが、このサイトは既に「文字コード変換エラーで壊れた記録」という体裁を持っているため、閲覧環境側で起きている異常として説明すれば技術的な不整合を吸収できると判断した。

### 決定
- **静的な演出**として、(1) 揺らぎ文字のメリハリ化（通常文字の揺れ幅・不透明度を減衰させ、由来記の核心語7語24文字のみ赤字・太字・強い揺れで強調）、(2) サイドバーのエラー情報ボックスへ「最終更新: 1978-00-00 00:00」「上書き試行: 3回（失敗）」の2行を追加、(3) 結びの一文を繰り返した上で尻切れにしフェードアウトさせる演出、の3点を実装した。（(1)は後日D-004により撤回。(2)(3)は維持）
- **アニメーション**として、(4) 読み込み時に一度だけサイトタイトル・見出しが明滅し静止する`kiroku-flicker-in`、(5) 由来記の核心語spanのみ9秒周期のうち終盤数%で不透明度とtext-shadowが一瞬乱れる`kiroku-glitch-pulse`（文字ごとに`animation-delay`をずらし同期させない）を実装した。いずれも各文字spanが個別に持つ`transform`（translate/rotate）は変更せず、opacity/text-shadowのみをアニメーションさせる設計とし、既存の「揺らぎ文字」の見た目を壊さないようにした。
- ユーザー提示の候補一覧のうち、常時動き続ける背景ノイズ（案C相当）と侵食の段階化（静的案B）は今回不採用とした（後述）。

### 理由
- ユーザーが、静的案の「メリハリ・エラー情報追加・結びの改ざん」とアニメーション案の「読み込み時の一度きりの明滅・間欠的な一瞬の乱れ」の組み合わせを明示的に選択した。
- 由来記本文の710文字を1文字ずつ手作業で編集するのは非現実的なため、Pythonスクリプトでspanのstyle属性を正規表現で解析・再生成する方式を採った。テキスト内容自体（文字そのもの）は結びの改ざん演出以外では一切変更していない。
- アニメーションはopacity/text-shadowのみを対象にした。`@keyframes`側で`transform`を上書きすると、各文字spanが個別に持つランダムなtranslate/rotate値が同じ変形値に収束し、既存の「文字ごとに向きも大きさも違う」揺らぎ演出が失われるため、その部分には触れない設計にした。

### 検討したが不採用の案
- **常時動き続ける背景ノイズ**: 「静止した記録を偶然開いてしまった」という既存のトーンと最も相性が悪いと事前検討で判断し、ユーザーにも非推奨として提示、ユーザーもこの案は選択しなかった。
- **文字化けの侵食を段階化する案**: 効果は見込めるものの本文の可読性設計への影響が大きく作業量も増えるため、ユーザーが選ばなかった。

### 影響
- 由来記の核心語（天女・磔・儀・祟り・供え・凶事・縛る）が視覚的に強調され、それ以外の本文は相対的に静かになったことで、既存の「均一な揺らぎ」よりも強弱のあるコントラストになった。
- 今後さらに演出を追加する場合、キーワード選定やGRAYSパレット等はスクリプト内にのみ存在し、リポジトリにファイルとして残していないため、同じ手法で拡張する際は本決定と`docs/progress.md`の該当エントリを参照してスクリプトを再構築する必要がある。

## D-004: T-003のメリハリ化（静的な色分け・太字強調）を撤回する

- 日付: 2026-09-02
- 状態: 採用

### 背景
- D-003で実装したメリハリ化は、由来記の核心語24文字を赤字（`#8a0000`）・太字・不透明度1に固定して静的に強調するものだった。
- ユーザーから、この静的な強調が「チープな演出になっており、相対的に恐怖効果が薄まっている」という指摘を受けた。強制的な色分け・太字による強調は、閲覧者に「ここが重要語です」と明示的に説明してしまう点で、由来記全体が持つ「見る人が自力で異常に気づく」という前提の不気味さと相性が悪い。

### 決定
- 核心語24文字の静的なスタイル（`color`・`font-weight`・`opacity`・揺れの強さ）を、D-003適用前の原文のランダム値へ完全に戻す。
- 核心語には、D-003で導入した`kiroku-glitch-pulse`アニメーション（9秒周期のうち終盤数%だけ一瞬乱れる、文字ごとにdelayをずらして同期させない）のみを残す。静止画としては原文と見分けがつかず、時間が経ってはじめてまれに一部の文字が揺らぐ、という形にした。
- D-003の(2)サイドバーのエラー情報追加、(3)結びの改ざん演出、(4)読み込み時の一度きりの明滅は、指摘の対象ではなかったためそのまま維持する。

### 理由
- ユーザーが明示的に「削除もしくは調整」を依頼し、静的な色分け・太字を撤回する調整（アニメーションのみ残す）を選択した。全廃（アニメーションも含めて削除）ではなく、ユーザーが元々承認していた間欠的なグリッチ演出（アニメーション案D）は活かす方が、直前のやり取りでの合意を尊重できると判断した。

### 影響
- 核心語は静止時に周囲の文字と見分けがつかなくなり、恐怖の所在を明示しない形になった。
- 作り直しの過程で、対象行の検出条件の誤りにより「今も、湖に、山に、物あるという。里の暮らしの中にもあるという。」の段落が結びの改ざん文で上書きされ消失する実装ミスを自己発見し、修正・検証済み（docs/progress.md T-004参照）。
